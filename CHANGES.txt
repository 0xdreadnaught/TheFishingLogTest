The Fishing Log (Test) - based on The Fishing Log 1.1.4

THIS IS A TEST BUILD, NOT THE MAIN ADDON. The main addon is The Fishing Log on
CurseForge. This build only sees anglers who run the test build.

Folder: TheFishingLogTest. Version line stays 1.1.4; the build number is the
X-Build line in the toc and shows in the journal title and diagnostics.

Build 7 - world probe, second pass
- The probe also lists game modes, the Forever experience preset, every game
  rule name, the values of the active rules, and whether chat channels are
  per world or regional. It no longer prints the surname.

Build 6 - world probe
- /tfl clientdiag also lists what the game client reports about the region and
  rule set this character is on. Read-only. It is there to find out how the
  addon can tell the worlds apart; nothing uses the answer yet.

Build 5 - says what it is
- A chat line at login, the AddOns list tooltip and the README all state that
  this is a test build, not the main addon, and that it only sees other test
  builds. The login line lives in TestBuild.lua.

Build 4 - a network of its own
- This build only talks to other copies of this build. It uses its own
  addon-message prefix (FishingLogTest, and TFLUIFaceTest for podium faces)
  and its own finder channel (TheFishingLogTest). Players on the original
  addon neither see nor receive anything from it, and the reverse.
- Save macros are named "TFL Test 1..4", so the original addon's account-wide
  "TFL Save" macros are never read or overwritten.
- The board's frenzy glow loads from this addon's own folder (it pointed at
  the original addon's folder).
- Card sharing refuses the finder channel by its current name.
- Message formats, the launch-date envelope and all shared tables are
  unchanged from 1.1.4.

Build 3 - sync alerts and reports

Sync alerts and reports:
- One clickable start toast and ding per batch of overlapping exchanges.
- A themed report opens after activity settles, deferred while in combat.
  It shows peers, routes, requests, received/sent totals, waters, and actual
  new/updated/season records with their holders and previous weights on hover.
- /tfl synclog reopens current/recent activity. Older/Newer browse the last
  ten reports; Copy exports the report and Realm opens the standings.
- Alerts & chat has Sync starts and Open reports after sync. Sounds has
  its own Sync starts switch. Existing global sound/toast switches apply.
- Completion is inferred: 20 seconds quiet with no queued/receiving transfers;
  requested data gets 120 seconds to arrive. Missing replies, errors, and
  expired transfers are marked. A handshake is not a delivered record book,
  and sent totals never claim the other client received them.
- Reports are local and bounded (ten reports, 32 peers and 160 record details
  per report); no extra traffic or protocol changes are introduced.

Transport/report regression checks and mocked report-window checks pass.
Live in-game display and player-to-player behavior still need confirmation.

Build 2 - record sync fixes:
- Whisper follow-ups return to the peer, including when guild/group routes
  are absent. The existing record tally also travels during whisper swaps.
- Routine books relay a rotating slice of all known species records, including
  records held by offline anglers. Own records and spot Kings retain priority.
  Books remain capped at 80 entries; send rate and peer-discovery limits stay
  the same. Rotation is per peer and bounded to 64 remembered cursors.
- Large multipart transfers expire after two minutes without new parts rather
  than two minutes from their start. Duplicate parts do not extend that timer;
  a 30-minute absolute lifetime and existing size/count caps remain in place.
- /tfl diag includes queued packets and completed/expired transfer counts.

Existing RBOOK/RBOOK2/RTALLY formats are preserved. Regression checks verify
legacy receivers, offline-holder relay, independent peer progress, cooldowns,
packet order/duplicates, and transfer timeouts. All Lua files pass parsing.
No live player-to-player test has been performed for this build.

This improves record propagation; it does not supply an authoritative realm
database or guarantee identical lists. Other clients still limit what they
send, disconnected peers cannot exchange data, and a full book can take
several exchanges. The change is most effective when other senders adopt it.

Build 1 - character layout:

The journal now keeps your character on the left third of the window. The
existing pages use the right two thirds, with all six bottom tabs preserved.
The window starts at 1140 x 620 and can be resized down to 1140 x 560.

The preview starts from your live character and applies selected, saved
fishing outfit pieces. Unchecked, unsaved, and saved-empty slots keep current
gear, matching the wardrobe's equip behavior. A saved fishing pole clears the
preview's off hand. The preview itself never equips or removes actual gear.
Drag the character to turn, scroll to zoom, or use Reset view. Outfit opens
the existing wardrobe. The preview refreshes when gear or outfit choices change.

Realm position above the character uses the addon's all-time record standings,
not the XP leaderboard or seasonal filter. These are the standings known from
shared records; hover for that context. Angler title and purple XP progress
appear below the character.

Godfall's existing community theme, artwork, widgets, and MIT attribution are
preserved. See LICENSE-UIRework.txt. This test build keeps its own saved data (the
game files it under the addon folder name) and remains dormant while the
original TheFishingLog is enabled.

Restart the client after installing this build to pick up the added Lua files.
Enable The Fishing Log (Test) with the original The Fishing Log disabled.
No data migration is needed.

Validation: all 88 Lua files parse as Lua 5.1; TOC entries and load order checked.
Mock-client checks cover outfit slot preservation, two-hand/off-hand behavior,
delayed loading and failures, event refresh, rank/XP, camera controls, journal
construction, bottom tabs, and workspace width. In-game rendering has not been
visually tested for this build.
